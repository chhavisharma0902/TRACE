# TRACE Backend (Member 4)

FastAPI layer between the recommendation engine (`graph-optimizer`) and the VS Code extension.
It loads `RecommendationEngine` **once at startup** and exposes it over HTTP.

## Setup

```bash
cd backend
python -m venv venv
venv\Scripts\activate          # Windows   (macOS/Linux: source venv/bin/activate)
pip install --upgrade pip
pip install -r requirements.txt
copy .env.example .env         # then put your GEMINI_API_KEY in .env
```

If the engine fails to import, install whatever `graph-optimizer` / `multigraph-builder`
need at runtime (see their `requirements.txt`).

## Input files (generated by teammates, not committed)

| File | Default location |
|---|---|
| Graph | `multigraph-builder/output/unified_graph.json` |
| Tuned weights | `graph-optimizer/output/best_weights.json` |
| Function line ranges | `ast-parser/output/function_ranges.json` |

Override any path in `.env` (`TRACE_GRAPH_FILE`, `TRACE_WEIGHTS_FILE`, `TRACE_FUNCTION_RANGES_FILE`).
No data yet? Run with `TRACE_USE_MOCK=1` to serve `mock_data/mock_recommendations.json`.

## Run

Always from `backend/` so `src` is importable:

```bash
uvicorn src.main:app --reload --port 8000
```

Swagger: http://localhost:8000/docs  ·  Health: http://localhost:8000/ (shows mode, node count, what failed to load)

## Test

```bash
python -m pytest -v
```

## API

IDs look like `src/app.py::Flask.run`. `recommend` and `ego-graph` accept **either** `function_id`
**or** `file_path` + `line` (1-based; VS Code lines are 0-based, so send `line + 1`).

| Method | Route | Notes |
|---|---|---|
| GET | `/api/recommend?function_id=...&k=5` | `{function_id, recommendations: [{function_id, score, via_call, via_cochange}]}` |
| GET | `/api/ego-graph?function_id=...&radius=1&max_nodes=25` | `{center, nodes, edges: [{source, target, edge_type, count}], truncated, total_nodes, total_edges}`. Radius 1-2; trimmed to the strongest `max_nodes` (the raw graph can be several MB) |
| POST | `/api/suggest-fix` | body `{function_id, diff, function_source?}` returns `{suggestion, auto_apply: false, ...}` |

Errors: `400` missing target, `422` bad parameter, `429` rate limited (see `Retry-After`),
`502` LLM failed, `503` engine/LLM not configured. Unknown functions return empty lists, never errors.

## Notes

- Paths are normalized to forward slashes on the way in.
- `suggest-fix` only returns text. The extension must display it and never apply it automatically.
- LLM calls are rate-limited server-side (per function and per minute). The extension should also
  debounce and call only on save or a button click.
- The free Gemini tier may use submitted content to improve Google's models: don't send code you can't share.
- Use a Python version with prebuilt wheels for all dependencies (3.11-3.13 are the safest).
