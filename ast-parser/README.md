# TRACE — Member 2: AST Parser / Static Dependency Analysis

This module implements the **AST Parser and Static Dependency Analysis** (Member 2) of the TRACE system. It performs static analysis of Python source code to extract function-level and class-method-level dependencies.

## Purpose

The AST Parser traverses a Python repository, parses its source files into Abstract Syntax Trees (ASTs), extracts defined functions, class methods, and call expressions, and resolves these calls to concrete target definitions in the codebase. The result is a clean, deterministic, and sorted dependency mapping that can be consumed by downstream tools (such as the Graph Optimizer).

## How it Works

1. **Repository Discovery (`file_finder.py`)**: Traverses the root folder recursively, identifying `.py` files and filtering out ignored directories like virtual envs (`.venv`, `venv`, `env`), build directories (`build`, `dist`), `.git`, and cache directories (`__pycache__`).
2. **Abstract Syntax Tree Extraction (`ast_visitor.py`)**: Uses Python's built-in `ast.NodeVisitor` to parse each file. It tracks scope stack entries (to support classes, nested functions, and class methods) and extracts defined functions, call expressions, and module imports.
3. **Import and Target Resolution (`path_resolver.py`)**:
   - Maps imports (absolute and relative) to physical files in the repository.
   - Resolves package initializers (`__init__.py`) and handles submodules.
   - Transitively traverses import structures to resolve re-exported symbols.
   - Maps call targets (local calls, self-calls, imported module calls, and class method calls) to their original function/method definitions.
4. **Serialization (`main.py`)**: Combines definitions and resolved calls, removes duplicates, sorts keys and values for reproducibility, and outputs a JSON file to `output/ast_dependencies.json`.

## Installation

This module is designed to run with **Python 3.11** and relies on the Python standard library (`ast`, `pathlib`, `os`, `json`, `argparse`), which does not require external installations.

To install dependencies required for testing:

```bash
pip install -r requirements.txt
```

## Usage

You can run the parser from the `ast-parser` directory using:

```bash
python src/main.py <path_to_repository_to_analyze>
```

### Example Command

To parse a repository located at `../shared_test_repo`:

```bash
python src/main.py ../shared_test_repo
```

## Example JSON Output

The output is written to `output/ast_dependencies.json` and follows a deterministic, sorted format:

```json
{
    "src/database.py::connect": [],
    "src/main.py::main": [
        "src/database.py::connect",
        "src/utils.py::helper"
    ],
    "src/utils.py::helper": []
}
```

## Known Limitations of Static Analysis

Since this parser relies on static AST analysis rather than runtime execution:
1. **Dynamic Dispatch**: Calls on object instances (e.g. `user.save()`) cannot always be statically resolved if the object type is not known. The parser resolves calls on `self` to class methods and class-level calls (e.g. `User.save(self)`) but skips dynamic runtime bindings.
2. **Dynamic Imports**: Imports performed inside conditional blocks or via `importlib.import_module` are not evaluated.
3. **Duck Typing / Reflection**: Built-in reflective functions like `getattr()` or `eval()` are not traced.
4. **Third-Party Libraries**: External dependencies (e.g. `requests`) and Python standard libraries are intentionally excluded from the repository dependency graph.
